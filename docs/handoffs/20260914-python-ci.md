## 2. Detailed Root Cause Analysis

### R1 — Packaged Calendar Integrity (`test_packaged_cache_has_complete_download_bundle`)
- **Location:** `sard/application/demo.py:669-674`, `sard/application/demo_cache/itinerary.ics`, `sard/application/demo_cache/manifest.json`.
- **Root Cause:** In the git repository, `sard/application/demo_cache/itinerary.ics` was checked in as a git blob with Unix LF line endings (`\n`, 82 lines, 3803 bytes, SHA-256 `fadfbce5010deab92066605a48117aaad99be3f49b029f3e7fbe55156a182d52`). However, `manifest.json` specifies the canonical RFC 5545 CRLF size (3885 bytes) and SHA-256 (`d3824c897c63661d185ecb82f990df55dfbb63fec0120afe92b1fbe95b05b835`), which is the exact output generated by `sard.outputs.calendar.render_calendar()`. On Ubuntu Linux runners in GitHub Actions (`ubuntu-latest`), git checked out the file with LF line endings. `load_precached_artifacts()` performed a strict byte-length and checksum check against `manifest.json`, failing with `DemoCacheUnavailable: packaged calendar integrity check failed`. On Windows platforms, git's `core.autocrlf` conversely converted `answer.txt` from LF to CRLF (2206 → 2223 bytes), causing `packaged raw_text integrity check failed`.

### R2 — Step 7 Offline Retained Calendar (`test_public_service_runs_offline_demo_and_retained_calendar_without_live_dependencies`)
- **Location:** `sard/application/demo.py:726`, `sard/application/service.py:167, 233, 456`.
- **Root Cause:** In `test_public_service_runs_offline_demo_and_retained_calendar_without_live_dependencies`, the test asks `SardApplicationService` to run the cached demo without trip dates or an explicit output root. `service._run_cached_demo` invokes `build_demo_result`, which delegates to `load_precached_artifacts()`. Because of R1 (integrity check failure), `load_precached_artifacts()` raised `DemoCacheUnavailable`. `_run_cached_demo` intercepted the exception and fell back to `_failed_result`, yielding a result with `itinerary=None`. When the test subsequently invoked `service.create_calendar_after_dates` on the retained result, `service._create_calendar_after_dates_serialized` threw `ApplicationServiceError: no_verified_itinerary ("لا يتوفر برنامج رحلة موثق لإنشاء التقويم.")`.

### R3 — Fallback Outcome on Live Graph Failure (`test_live_failure_automatically_uses_visible_cached_fallback`)
- **Location:** `sard/application/service.py:437, 446`, `sard/application/demo.py:726`.
- **Root Cause:** When a live graph execution fails, `SardApplicationService._stream_live_with_auto_fallback` falls back to `self._run_cached_demo(cached_request)`. Due to R1, `build_demo_result` failed to load the packaged cache and returned a failed result (`graph_outcome="failed"`). The test asserted `assert result.graph_outcome == "completed"`, which failed with `assert 'failed' == 'completed'`.

### R4 — Health Expected Ok vs Degraded (`test_health_endpoint` in `tests/test_api.py`)
- **Location:** `sard/api/server.py:482-487`, `tests/test_api.py:30, 37`.
- **Root Cause:** `sard/api/server.py` implemented truthful health reporting ("truthful, never always-ok"). When no model provider API keys are configured in the environment (as in offline CI), `_is_model_configured()` evaluates to `False`. `/api/health` strictly reports `"status": "degraded"` when unconfigured or when inference fails. `tests/test_production_contract.py:42` and `tests/test_e2e_multiagent_verification.py:80` accommodate this with `assert data["status"] in ("ok", "degraded", "unavailable")`. However, `tests/test_api.py` lines 30 and 37 contained rigid assertions `assert data["status"] == "ok"`, failing with `assert 'degraded' == 'ok'`.

### R5 — Sadu E2E Required Model (`test_chat_sadu_cultural_query_grounded_citations` in `tests/test_e2e_multiagent_verification.py`)
- **Location:** `tests/test_e2e_multiagent_verification.py:102-120`, `sard/api/server.py:1262-1268, 1464`.
- **Root Cause:** The test posts an Arabic cultural query regarding Sadu heritage to `/api/chat`. In offline CI without live LLM provider keys, `ChatService` cannot generate narrative synthesis and falls back to `_generate_cultural_fallback_answer`. This emits the knowledge-integrity refusal: `"حفاظًا على الأمانة المعرفية، لا أقدّم توليفًا غير مُسنَد بلا مصادر"`. Line 120 of `test_e2e_multiagent_verification.py` explicitly asserts `assert "حفاظًا على الأمانة المعرفية، لا أقدّم توليفًا غير مُسنَد" not in full_text`. Because offline CI lacks a model, the refusal message is present, failing the assertion.

### R6 — JSON Fastpath Required Model (`test_gap_g10_json_deadline.py`)
- **Location:** `sard/agent/chat_service.py:331-342`, `tests/test_gap_g10_json_deadline.py:9-16`.
- **Root Cause:** In `test_gap_g10_json_deadline.py`, line 10 states: `# Inject a dummy model to avoid live keys? Use fastpath which skips planner entirely.` However, line 9 instantiated `svc = ChatService(chat_model=None, orchestrator=None)`. In `sard/agent/chat_service.py`, lines 331-342 check `if self._injected_model is None: self._get_model()`, which raises `ModelConfigError` when no provider is set. This check preceded the G10 structured fastpath at lines 346-350, preventing the fastpath from executing and causing `svc.ask()` to return `ChatResult(ok=False)`.
