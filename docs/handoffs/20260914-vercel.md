## Root cause

`vercel.json` defined two overlapping `functions` patterns with identical
config over a single file (`api/` contains only `index.py`):

- `api/**/*.py` and `api/index.py` both match `api/index.py`
  (verified locally: both globs match the one file).

Vercel's `functions` validation (`unmatched-function-pattern`) reported
`api/index.py` as matching no Serverless Function. The redundant duplicate
is the direct trigger: the failing pattern string is one of the two
overlapping keys, and the config was introduced in `0f45882` on top of the
previously working `12b15af` config (which had rewrites only, no
`functions` block).

Contributing fragility in the owned entrypoint: `api/index.py` only did
`from sard.api.server import app` (bare re-export, CRLF, no explicit
assignment, no direct FastAPI reference), which is easy for static
entrypoint detectors to miss. Vercel Python docs require each `/api` file
to define a top-level `app`/`application`/`handler`, and framework guides
show an explicit assignment.
