## Root cause

The existing calibrated lexical score measured proximity, not cultural identity. A single generic overlap could therefore surface an unrelated Fashion/Crafts or regional record as evidence. The planner also exposed internal citation IDs to the API even when the raw L0 record had the real URL. Deterministic rewrite sanitization discarded safe Arabic equivalents, and degraded server fallback code still contained topic-specific shrimp/springs answers. Direct-model history could carry an earlier topic into a later degraded turn.

## Implemented path

The path now remains:

`prompt → intent/classification → Isnād planning → RAG/local/web retrieval → L0 raw evidence → entity/region/mandate relevance → provenance score/decision → grounded answer or hedge → ChatService → API SSE → frontend parser`

`sard/rag/relevance.py` is the shared gate. Recognized entities are matched against the current query and evidence topic/anchor, explicit sector and region conflicts are rejected, and unknown queries require meaningful overlap. The gate annotates entity, region, mandate, matched-topic, and overlap metadata for downstream auditability. It is applied after bundled/Zvec/local fusion, again at the cultural router boundary, and again before planner evidence is exposed or generated.

The four supported cultural cases are covered by aliases and the bundled/local evidence path:

- Eastern-coast shrimp drying: existing curated coastal records.
- Al-Ahsa hot springs: existing curated springs records; therapeutic language is qualified as local belief/use, not medical evidence.
- Saudi coffee and majlis: the bundled culinary record.
- Southern bread: added the Asir Development Authority’s local-flavors record, paraphrased with provenance at <https://www.asda.gov.sa/ar/from-aseer/authenticity/local-flavors>.

Strong-only proposal gating now prevents recipe cards, artisan-craft outputs, and etiquette simulators from reaching the renderer without a strong, entity-matched, mandate-matched citation. Generic document requests retain their existing behavior. Planner citations recover the raw source URL and stable citation ID; the API emits only valid HTTP(S) citations and always preserves `session_id`/`run_id` in `done`.
